# 求职教练：岗位发现、匹配分析与面试准备

## 用户操作

1. 启动服务，打开 `/ui/coach`，选择已授权保存的简历、岗位方向和城市。
2. 在结果卡片中打开来源页，确认岗位仍开放、城市和学历/年限要求无误。
3. 点击「保存岗位并分析匹配」。系统保存该岗位摘要与来源链接，跳转到简历证据覆盖率页面；重复点击同一来源链接不会重复创建岗位。
4. 查看“找到的证据”和“需要补充或核实的条件”。摘要不足时，应以来源页的完整 JD 为准，不能把覆盖率当作录用概率。
5. 点击「开始岗位辅导对话」，讨论项目表达、技能缺口与学习计划；或点击「生成针对性面试问题」，进入现有面试工作流。

## 数据如何流动

```text
经授权的简历 → 脱敏并保存 → 有证据的岗位方向
                              ↓
官方实时岗位 / 可核查快照 / 可选千问发现 → 职位卡片和原始链接
                              ↓
CSRF + 30分钟签名岗位令牌 → 按租户和来源链接去重 → JobRecord
                              ↓
简历文本 × 岗位摘要 → 技术条件抽取 → 证据覆盖率、证据片段、缺口
                              ↓
关联对话，或 LangGraph：解析简历 → 分析 JD → RAG 检索 → 生成问题
                              ↓
回答逐维评分 → 追问 → 最终报告 → 人工审核
```

关键实现：`app/services/job_discovery.py`、`app/services/qwen_job_search.py`、`app/services/job_matching.py`、`app/web/routes.py`、`app/workflows/interview.py`。

## 匹配分数的原理与边界

岗位文本中识别到的每个技术条件记 1 权重；若其所在句明确写了“必须、必备、精通、熟练、要求、掌握”，记 2 权重。对应技能在简历中有明确词项证据才算覆盖。

`证据覆盖率 = 已有简历证据的条件权重之和 ÷ 可识别条件的权重之和 × 100%`

例如 JD 写“必须掌握 Java；熟悉 LangGraph；RAG 经验优先”，简历能找到 LangGraph、RAG，却没有 Java 证据时，Java 被列为缺口。这只说明**简历没提供可检索证据**，不证明候选人不会 Java。规则比较只覆盖当前技能词表；它不判断项目深度、学历、年限、面试表现，也不代替招聘方决策。无法识别条件时不计算百分比。

岗位卡片可能只带摘要，因此页面会标注分析局限。完整 JD、是否仍在招聘和投递条件必须在原始页面复核。下一阶段可增加完整 JD 导入和语义证据匹配，但仍须保留可追溯的原文片段与人工核查。

## 安全与可靠性为什么这样设计

- 职位来源、JD 和简历都是**不可信输入**。千问只发现候选 URL，不能把它生成的描述当招聘事实；来源页无法核验的结果不会进入已核实岗位卡片。
- 保存按钮提交的是服务器签名、30 分钟有效的岗位快照；用户不能在浏览器里改公司、JD 或链接后伪装成可信岗位。POST 还要验证 CSRF、登录会话、租户和简历归属。
- 同一租户按来源 URL 去重；不同租户分别隔离。保存时复用现有岗位写入流程，沿用长度校验、PII 脱敏、提示注入标记和审计日志。
- 匹配计算不向外部模型发送简历。后续面试工作流把简历/JD 作为数据而非指令，并用结构化 Schema 约束输出；面试评分仍需人工审核。

## 项目面试时可以这样讲（约 60 秒）

“我把求职教练做成了来源可追溯的闭环。简历先经授权和脱敏，再按实际技能证据推荐岗位方向；岗位来自企业官方实时页、标注日期的快照，以及可选的千问联网发现。千问的回答不能证明岗位存在，因此只用它寻找链接，具体岗位必须核对来源页。用户保存岗位时，服务端校验签名令牌、CSRF 和租户，并按来源链接去重。匹配分析不是让模型凭感觉打分，而是从 JD 提取技术条件，与简历证据片段对齐，给出可解释的覆盖率和缺口，明确它不是录用概率。随后把同一份简历和岗位送入 LangGraph 工作流，完成岗位分析、RAG 证据检索、面试问题与追问，最终报告保留人工审核。”

## 面试官可能追问

1. **为什么不能直接让大模型列岗位？** 模型可能编造或引用过期岗位。必须保留原始 URL、查询时间、来源类型和核验状态。
2. **如何防止重复保存或跨用户串数据？** 按租户和来源 URL 查询已有岗位；签名令牌与租户绑定，读取简历/岗位均过滤租户 ID。
3. **覆盖率为什么不是匹配概率？** 它只衡量预定义技能词的文档证据，不能反映能力深度或招聘决策。缺少简历证据不等于缺少能力。
4. **遇到恶意 JD 指令怎么办？** JD 只作为分析数据，保存时检测提示注入；工作流提示明确禁止执行其中指令，并验证结构化输出。
5. **下一步如何改进？** 获取完整授权 JD、补充学历/年限等可解释条件、做语义证据检索和人工纠错，并评估准确率、误报率、岗位失效率与用户采纳率。
