# 企业上线检查表

任何一项回答“不清楚”，都不应直接全量上线。

## 业务与责任

- [ ] 场景、用户、成功指标和明确禁止的用途已书面化；
- [ ] 有业务 Owner、技术 Owner、安全 Owner 和人工审核责任人；
- [ ] 模型输出标明“决策辅助”，有申诉和纠错流程；
- [ ] 失败或模型不可用时有人工降级路径。

## 数据与隐私

- [ ] 候选人已知情并授权处理其数据；
- [ ] 只采集完成任务必需的数据；
- [ ] 定义保留期限、删除、导出、更正和访问流程；
- [ ] 传输和静态存储加密；
- [ ] 备份同样加密且定期做恢复演练；
- [ ] 知识文档来源、所有者、许可、有效期可追溯。

## 安全

- [ ] 旧的明文 DashScope Key 已吊销；
- [ ] 密钥进入 Vault/KMS/云密钥服务，不写代码和日志；
- [ ] 使用 SSO/OIDC、RBAC 和服务身份；
- [ ] PostgreSQL 启用强制租户过滤或 Row-Level Security；
- [ ] API 有速率限制、请求大小限制、WAF 和 TLS；
- [ ] 工具遵守最小权限，高风险副作用需要批准；
- [ ] 完成依赖、镜像、代码、Prompt Injection 与越权测试。

## 模型质量

- [ ] 有版本化黄金数据集和人工评分指南；
- [ ] 测过结构化成功率、检索召回、引用准确性和幻觉率；
- [ ] 测过不同群体的错误率和人工改判率；
- [ ] 新模型、Prompt、知识库先离线评测再灰度；
- [ ] 有模型超时、重试、熔断、预算和降级模型。

## 工程运行

- [ ] 数据库通过 Alembic 管理，迁移有回滚和备份方案；
- [ ] 长耗时任务进入队列，支持幂等、取消和死信；
- [ ] 日志、指标、分布式追踪和告警已经接入；
- [ ] 日志不含简历全文、答案全文、密钥或敏感 Prompt；
- [ ] 定义 SLO：可用性、P95 延迟、错误率、成本；
- [ ] 进行容量压测、故障注入和灾难恢复演练；
- [ ] 值班、事件分级、停机开关和复盘流程明确。
